# Paper — scope "water": the greetings part (0x24df, per-tick callback 0x26aa)

Ticks 7741–8818 (music counter 909..1037; part target [0x1ea8f] = 0x400 = 1024). All addresses code32.
Everything below was checked **bit-exactly** against the emulator: a hooked copy of run_paper.py resumed from
the t7000 snapshot dumped the wave records, the 41x26 grid, the height map after the warp, after the text, and
the finished VGA frame for 10 frames spread over the part, plus the state at every tick. A Python model of the
routines described here reproduces all of them with zero differing bytes, and the palette for all 1074 ticks
(scripts gen.py, model.py, pal.py, slots.py in the scratch dir
paper/re/models/water/). The hooked run is identical to full.frames over
the whole part (except tick 8700, which is where the reference capture was joined).

## 1. What it draws

A purple, metallic-looking surface that slowly undulates, lit by one light that moves on an ellipse, with greetings
names embossed into it. The names don't scroll. They fade in and out of the surface on four fixed lines, one
line at a time, round-robin. There is **no water simulation** (no ripple propagation, no previous-frame state):
the "water" is a static 256x256 kaleidoscope texture, used as a **height map**, warped through a smooth biquadratic
patch whose 3x3 control points are sums of 72 sine oscillators. It is then bump-mapped (environment/light-map lookup by
height gradient). The palette's base hue rotates over the part (grey-blue → purple → pink → brown).

- tick 7741–7743: precalc (callback 0, glyph strip + blur), screen black.
- tick 7744: callback 0x26aa installed, fade-in starts (level +400/tick, full at tick 7825).
- music counter reaches 1024 at tick 8705; the main loop then sets fade target 0, step 300 (0x12c) → black at
  tick 8816; part exits, tick 8818 the plane flock (0x388b) starts.

## 2. Data generated at program init (not in this part, but used by it)

### 2a. Texture bank 0 at [0x1eddd] (256x256 bytes, 64K-aligned) — 0x10d3
Static source: **64x64 4-bit image at code32 0x16ca3** (2048 bytes, row-major, 32 bytes per row, high nibble =
left pixel). Exactly regenerated by:
```c
u8 tex[256][256];
for (r = 0; r < 64; r++) for (c = 0; c < 32; c++) {
    u8 b = SRC[0x16ca3 + r*32 + c], hi = (b>>4)*16, lo = (b&15)*16;
    for (rr = 2*r; rr <= 2*r+1; rr++) {               // each nibble = 2x2 texels
        tex[rr][4*c+0] = tex[rr][4*c+1] = hi;  tex[rr][4*c+2] = tex[rr][4*c+3] = lo;
        tex[rr][255-4*c] = tex[rr][254-4*c] = hi; tex[rr][253-4*c] = tex[rr][252-4*c] = lo;  // mirror in x
    }
}
// point mirror of the whole 64 KB: tex_flat[0xffff-k] = tex_flat[k]  → rows 128..255 = rows 127..0
for (it = 0; it < 3; it++) {           // 3 x (two passes of the cross blur, then shift by (-2,-2)), toroidal
    // scratch: 260 rows x 260 cols; scratch[y][x] = tex[y & 255][x & 255]
    // pass A: tmp[y][x] = (s[y-1][x] + s[y+1][x] + s[y][x-1] + s[y][x+1]) >> 2   (integer)
    // pass B: s[y][x]   = (tmp[y-1][x] + tmp[y+1][x] + tmp[y][x-1] + tmp[y][x+1]) >> 2
    // tex[y][x] = s[y+2][x+2]          (the copy back starts at row 2, column 2: 0x20a = 2*260+2)
}
```
Net effect: 4-way kaleidoscope of a 128x128 quadrant (the 64x64 nibble image pixel-doubled), blurred by 6 passes
of the 4-neighbour cross kernel (no centre tap, ≈ Gaussian σ ≈ 1.73 texels per axis), wrapped, shifted by
(−6,−6) texels. Values 0..240. (Bank 1, [0x1eddd]+0x10000, belongs to the teal-plane part; this part uses bank 0.)

### 2b. Shade/multiply table T2 at [0x1eded]+0x10000 (rows 0..64 of 256 bytes) — 0x144b
`T2[l][c] = min(255, (c*l) >> 5)` for l = 0..64. This part adds 0x10000 to [0x1eded] at entry (so the warp and text
routines use T2) and subtracts it at exit. Only rows 20 and 0..32 are used here: **height = c*l/32**.

### 2c. Light (environment) map at [0x1edd1] — 512 x 256 bytes, 512-aligned — 0xc80 (FPU)
Exactly regenerated by (fistp = round to nearest even, default FPU mode):
```c
for (j = 0; j < 256; j++) for (i = 0; i < 512; i++) {
    int x = i - 256, y = j - 128;
    int d = lrint(32.0 * sqrt(sqrt((double)(x*x + y*y))));     // 32 * r^0.5
    int v = 300 - d;  v = clamp(v, 0, 255);
    if (v > 192) v = (v - 128) & 255;          // bright core: 65..127
    else         v = (v * 0x5555) >> 16;       // glow: ≈ v/3, 0..63
    u8 a = (u8)(v << 1);  a -= a >> 3;         // ≈ 1.75*v
    int t = tex[(-j) & 255][(-i) & 255] >> 1;  // bank-0 texture at init time, half strength, mirrored
    LM[j][i] = min(255, a + t);
}
```
Radial profile (r in light-map texels): core r ≤ 2.0 → 223; falls to 114 at r ≈ 11.3; there it **steps down** to 111
(v 193 → 192: the edge of the hot spot; keep it); then glow ≈ (2/3·(300−32√r))·7/8 down to 0 at r ≈ 87.9.
The added texture is the "metallic reflection" pattern. The light centre is LM texel (256,128).

### 2d. Font at [0x1ede9] — 0xe2e; static RLE data at code32 0x18ed7..0x19692
29 glyphs (a..z, then '{' '|' '}' used by the logo), 2048 bytes each: byte 0 = width, then 32 rows at stride 60
(row r at offset 1 + 60r). 1-bit (0 / 255). Row encoding: bytes until 0; byte b == 0xff → skip = next byte,
count = byte after; else skip = b & 15, count = b >> 4 (count 0 means 256); `x += skip`, then `count` pixels of 255.
Helvetica/Arial-like lowercase sans; ascenders from font row 1, x-height from row 7, baseline row 21–22, descenders
to row 28. Widths a..z: 28 30 27 30 29 20 30 28 8 14 26 8 44 28 32 30 30 19 29 19 28 31 49 29 29 28.

## 3. Part setup — 0x24df
```c
state_loading = 0;                // [0x1ea94]
next_name     = 0x23e8;           // [0x22465] string list pointer
[0xeb8]       = 0x34;             // self-mod: row stride of the glyph blitter 0xe8a = 52
// glyph strip at [0x1edcd]: 26 cells of 52 x 64 bytes (cell g at offset g*0xd00)
for (ch = 'a'; ch <= 'z'; ch++) {
    u8 cell[32][52] = {0};
    blit glyph ch at cell[0][2] (saturating add of the 0/255 font bytes; width = font width byte, 32 rows);
    for (r = 0; r < 32; r++) strip[g][2r] = strip[g][2r+1] = cell[r];   // doubled vertically → 52 x 64
}
blur2(strip + 52, 1662 rows, stride 52);  blur2(strip + 52, 1662, 52);  // 0xf47 twice = 4 cross-blur passes
[0x2efc] = 6; [0x2f02] = 6;       // self-mod shift counts in 0x2dc8: grid a = Y<<6, b = X<<6
init_waves(200);                  // 0x2756, ebx = 0xc8
[0x22461] = 0;                    // dead store here
grid[*].shade = 0x1400;           // 0x2db3: constant shade 20.0 (8.8) in every grid vertex
[0x1eded] += 0x10000;             // use T2
pal_angle = 0x944; pal_shift = 11;   // self-mod: [0x14dd] (mov ebx,imm) and [0x1505] (mov cl,imm)
make_palette();                   // 0x14dc (uploaded at the current fade level, 0 = black)
clear VGA;                        // 0x5b6b
fade_target = 0x8000; fade_step = 0x190;   // 400/tick → 82 ticks
callback = 0x26aa;
do {                               // main loop, once per drawn frame
    build_grid();                  // 0x2dc8
    warp(hmap);                    // 0x3095 into [0x1edc9] (320 x 200 height map, rows 200/201 spare)
    for (s = 0; s < 4; s++) if (slot[s].str) draw_string(slot[s].str, slot[s].level, x = 5, y = 46*s);
    a = light_angle;               // [0x22469]
    A = SIN[a & 1023] >> 10;  E = SIN[(a+256) & 1023] >> 12;   // floor(64 sin), floor(16 cos)
    bump(A, E);                    // 0xd28, writes VGA directly (no back buffer in this part)
    key check (0x7a64);
    if (music_counter >= 0x400) { fade_target = 0; fade_step = 0x12c; }
} while (fade_level != 0);
callback = 0; [0x1eded] -= 0x10000; pal_shift = 12;
```
`blur2` (0xf47/0xf90), exactly: `tmp[i] = (p[i-stride]+p[i+stride]+p[i-1]+p[i+1])>>2` for i in [0,n), tmp with 640
zero bytes before/after; then `p[i] = (tmp[i-stride]+tmp[i+stride]+tmp[i-1]+tmp[i+1])>>2`. In the strip the ±1
neighbours run across the 52-byte row ends (glyphs sit at columns 2..50, so no visible bleed); after the 4 passes
the strongest central difference over 2 px is 126. The warped background measured at most 91 over all 717 frames,
and max() compositing can't exceed either input's difference. So the byte gradient in the bump step never wraps in
this part (in principle a background difference ≥ 128 would wrap).

### Waves: 0x2756 (ebx = 200) and their data
72 records {phase, amp, speed} (int32) at [0x1edd5]:
`phase = rnd(); amp = (rnd() & 0x3ff) + 0x100; speed = (((rnd() & 0xff) - 0x80) * 200) >> 8;` (amp 256..1279,
speed −100..99). rnd = 0xaa2: additive lagged Fibonacci, 64 dwords at 0x9a0, indices j=[0xaa0], k=[0xaa1]:
`v = s[j] + s[k]; s[k] = v; j = (j+1)&63; k = (k+1)&63; return v`. Its state here depends only on earlier set-ups
(every 0xaa2 caller before this part runs once per part, not per frame), so the values are machine-independent.

octave. The original stores them interleaved: record ((j*3+i)*4 + o)*2 + {0:x, 1:y}, octave o = 0..3 ↔ cl = 4,3,2,1:

## 4. Per-tick callback — 0x26aa (in the 70 Hz IRQ, after the music player and the fade step)
```c
if (player_subtick > 3) {          // [0x1e4e6]: counts 6,5,...,1 per player call (speed 6), 6 = new row
    make_palette(pal_angle);       // 0x14dc → buffer 0x1eaad + upload (0x15c0) at the current fade level
    pal_angle++;                   // [0x14dd]
}
light_angle++;                     // [0x22469]
names_step();                      // 0x2478
for (r = 0; r < 72; r++) wave[r].phase += wave[r].speed;   // 0x26d0
```
The player runs exactly 5 times per 7 IRQ ticks (accumulator −0x4295 per tick, +0x5d37 per call → 50.0 Hz), speed 6
→ one music row = 8.4 ticks. `player_subtick > 3` holds for the first 3 of the 6 player calls in each row, so the
palette angle advances 1 per tick during the first half of each row: exactly 21 per 42 ticks = 35.0/s on average
(measured 538 steps in 1073 ticks). The palette shown at any time is built from `pal_angle − 1` (the value before its
last increment; 0x944 before the first one).

### Names — 0x2478, table at 0x2464 (4 slots x {u8 level; u32 str}), slot index [0x2460], state [0x1ea94]
```c
Slot *s = &slot[cur];                         // cur = [0x2460], starts 0; all slots start {0, NULL}
if (state_loading) {                          // fading the new name in
    if (++s->level == 0x20) { state_loading = 0; cur = (cur + 1) & 3; }
} else if (s->level == 0) {                   // empty: take the next name
    state_loading = 1; s->str = next_name;
    next_name += strlen(next_name) + 1; if (*next_name == 0) next_name = 0x23e8;
} else s->level--;                            // fading the old name out
```
Strings (NUL-separated at 0x23e8, list ends with an empty string): `" " " " " " " " "hello" "     jamm" "halcyon"
"   orange" "   bullfrog" "subliminal" "     acme" "valhalla" "oxygene" "    cubic" "amen" "     pulse"`. Leading spaces are
indentation (30 px each). So each line takes 1 + 32 ticks for the first four blanks, then 65 ticks per line
(32 down, 1 load, 32 up). Load ticks (verified): blanks 7744/7777/7810/7843 (slots 0..3), hello 7908 (slot 0),
jamm 7973 (1), halcyon 8038 (2), orange 8103 (3), bullfrog 8168 (0), subliminal 8233 (1), acme 8298 (2), valhalla
8363 (3), oxygene 8428 (0), cubic 8493 (1), amen 8558 (2), pulse 8623 (3), blank 8688 (0), blank 8753 (1). A name
is at full level 32 ticks after its load. It starts fading out 228 ticks after its load, when its line comes
round again, and is gone at 260 ticks, when the next name is loaded into that line. At the end amen and pulse are still up and fade with the palette.

Screen positions (glyph cell left edge x0 = 5 + 30*spaces, line y = 46*slot; cells 52 x 64, glyph ink from x0+2):
hello 5, jamm 155, halcyon 5, orange 95, bullfrog 95, subliminal 5, acme 155, valhalla 5, oxygene 5, cubic 125,
amen 5, pulse 155. Advance per letter = width + 4.

## 5. Per-frame rendering (pure function of the per-tick state)

### 5a. Grid of texture coordinates — 0x2dc8 (+ 0x2ad0)
```c
// control points P[j][i] (j = row 0..2, i = column 0..2), each {x, y}
int rec = 0;
for (j..) for (i..) { int sx = 0, sy = 0;
    for (cl = 4; cl >= 1; cl--) {
        W *w = &wave[rec++]; int idx = ((w->phase << cl) >> 7) & 0x3ff;   // int32 shifts
        sx += ((SIN[idx] * w->amp) >> 16) >> cl;                          // arithmetic shifts (floor)
        w = &wave[rec++];    idx = ((w->phase << cl) >> 7) & 0x3ff;
        sy += ((SIN[idx] * w->amp) >> 16) >> cl;
    }
    P[j][i] = {sx, sy};
}
// 0x2ad0: quadratic through P0 (s=0), P1 (s=1/2), P2 (s=1), evaluated at n+1 points, integer:
void quad(int P0, int P1, int P2, int n, int *out) {
    int step = (65536 / n) >> 7;                // n = 40 → 12, n = 25 → 20   (exact would be 12.8 / 20.48)
    int b = 4*P1 - P2 - 3*P0, c = P0 - 2*P1 + P2;
    for (k = 0, e = 0; k <= n; k++, e += step)
        out[k] = ((((b*e) + ((c*e*e) >> 8)) >> 8) + 2*P0) >> 1;   // = P0 + b·s + 2c·s², s = e/512
}
for (j..) { quad(P[j][0].x, P[j][1].x, P[j][2].x, 40, RX[j]); quad(P[j][0].y, .., 40, RY[j]); }
for (k = 0; k <= 40; k++) {
    quad(RX[0][k], RX[1][k], RX[2][k], 25, X); quad(RY[0][k], RY[1][k], RY[2][k], 25, Y);
    for (r = 0; r <= 25; r++) { grid[r][k].a = Y[r] << 6; grid[r][k].b = X[r] << 6; }   // shift 6/6 (self-mod)
}
```
So screen column x ↔ patch parameter s = x·3/1024 (0 .. 0.9375 at x = 320) and screen row y ↔ t = y·5/1024
(0 .. 0.977 at y = 200). This truncation is part of the look, so keep it. X and Y are in quarter texels: the texture is
addressed at column X/4, row Y/4 (mod 256). The control points move by up to about ±1200 quarter texels (±300 texels).

Oscillator frequencies: octave cl advances the table index by speed·2^cl/128 per tick: period 8192/|speed| ticks
for cl = 4 (≥ 82 ticks ≈ 1.2 s), 65536/|speed| for cl = 1 (≥ 655 ticks ≈ 9.4 s). Amplitude amp/2^cl.

### 5b. Warp renderer (height map) — 0x3095
40x25 blocks of 8x8 pixels, vertices = grid (41x26 records of {a, b, shade} 8.8 fixed, 12 bytes). Per block with
vertices V00 (top-left), V10 (top-right), V01, V11, for each channel c ∈ {a, b, shade}:
```c
dx  = (V10.c - V00.c) >> 3;                         // per pixel along the top edge
ddx = ((V11.c - V01.c) - (V10.c - V00.c)) >> 6;     // change of dx per row
dy  = (V01.c - V00.c) >> 3;                         // left edge per row
val(px, py) = (V00.c + py*dy + px*(dx + py*ddx)) & 0xffff;     // exact (the asm keeps a and b in one 40-bit
                                                                 // register with a guard byte; they never interact)
hmap[8R+py][8K+px] = T2[shade >> 8][ tex[a >> 8][b >> 8] ];     // shade = 0x1400 → height = tex*20/32 (0..159)
```
This is bilinear interpolation of the biquadratic patch over 8x8 blocks with nearest-texel lookup. The remake should
evaluate the patch per pixel (§7).

### 5c. Text into the height map — 0x26e7 / 0x2700
```c
draw_string(str, level, x = 5, y = 46*slot):   // 0x26e7
    for (ch in str) if (ch == ' ') x += 30; else { draw_letter(ch, level, x, y); x += width[ch] + 4; }
draw_letter: for (r = 0; r < 64; r++) for (c = 0; c < 52; c++)   // 0x2700, linear addressing, stride 320
    hmap[y+r][x+c] = max(hmap[y+r][x+c], T2[level][strip[ch][r][c]]);    // = glyph·level/32, level 0..32
```
At level 32 the letter plateau is 255, above any background height (≤ 159), so the letters always stand out. The
plateau is flat, so the light-map texel under it is the one a flat surface would get. You only see the letters by their
bevelled edges and the surrounding relief.

### 5d. Bump / environment lighting — 0xd28 (writes VGA directly)
```c
A = SIN[a & 1023] >> 10;  E = SIN[(a + 256) & 1023] >> 12;     // a = light_angle
row 0 and row 199 = 0; columns 0 and 319 = 0;
for (y = 1; y <= 198; y++) for (x = 0; x < 320; x++) {
    int gx = (u8)(h[y][x-1] + 0x80 - h[y][x+1]) >> 1;           // 0..127, flat = 64 (byte arithmetic)
    int gy = (u8)(h[y-1][x] + 0x80 - h[y+1][x]) >> 1;
    vga[y][x] = LM_flat[(14 + E + (y >> 1) + gy) * 512 + (112 + A + (x >> 1) + gx)];
}
```
The VGA value is the palette index. The light map is read at half resolution (one texel per 2x2 screen pixels) and
offset by half the central difference of the height. On a flat area the light centre (LM 256,128) is at screen
x = 160 − 2A, y = 100 − 2E: the light swings ±128 px horizontally and ±32 px vertically on an ellipse. It starts at
angle 89 (left of centre) and makes 1.05 turns over the part. Out-of-range rows (−1, 256) are only possible at
the most extreme gradients on rows 1–2 or 197–198. Clamp them in a port.

### 5e. Palette — 0x14dc (angle in [0x14dd], shift [0x1505] = 11 in this part) and upload 0x15c0
```c
s  = SIN[ang & 1023] >> 11;              // ±32
c  = SIN[(ang + 256) & 1023] >> 11;
c2 = (c * 0xde) >> 8;                    // ±27.75
R = 128 - s;  G = 128 + (s >> 1) + c2;  B = 128 + (s >> 1) - c2;   // (bytes; no wrap in range)
for (i = 0; i < 128; i++)  pal[i]     = { R*i >> 9, G*i >> 9, B*i >> 9 };                   // black → base/4
for (k = 0; k < 128; k++)  pal[128+k] = { (R*(128-k) >> 9) + (k >> 1), ... };               // base/4 → 63 (white)
// upload with fade level L = fade_level >> 8:
//   L <= 0x80: dac = pal*L >> 7;   else (not used here): bl = min(L,255)-128; dac = ((pal*(127-bl) >> 6) + bl) >> 1
```
Values are 6-bit DAC (0..63). Measured base colours: tick 7744 ang 324 → (99,130,154) blue-grey; 8000 → (117,106,160)
purple; 8400 → (153,96,134) pink; 8800 → (156,127,101) brown. In true colour: index i < 128 → base·i/128, index
128+k → lerp(base, white, k/128), with base = (R,G,B)/256 (·64/63).

## 6. Time bases

| variable | where | time base | rate |
|---|---|---|---|
| wave phases (72) | 0x26d0 in 0x26aa | per tick | phase += speed (−100..99) |
| light angle [0x22469] | 0x26aa | per tick | +1; 1024 per turn = 14.63 s; starts at 88 (left over from the 3D scene, where it is a scratch variable); first frame uses 89 |
| palette angle [0x14dd] | 0x26aa | per tick, gated by the music | +1 on ticks where player sub-tick ∈ {6,5,4} (first half of each row): 0.5/tick avg = 35.0/s; 0x944 → 2910 at the end |
| name slot levels | 0x2478 | per tick | ±1 per tick on one slot at a time (see §4) |
| fade level [0x1edb5] | IRQ | per tick | +400 (fade-in, 82 ticks), −300 after counter ≥ 1024 (110 ticks) |
| grid, warp, text, bump | main loop | per frame | rendering only, no state |

**Nothing advances per frame.** The part is frame-rate independent. Measured in full.ticks: 717 frames in ticks
7744–8817 (1074 ticks) = 0.668 frames/tick = 46.7 fps at the 1.5M-instructions/tick budget, i.e. ≈ 2.25M
instructions per frame. A remake can render at display rate and evaluate the per-tick quantities at fractional tick
time `n = (t − t0)·70.0018` (n = 1 is the first callback, tick 7744): phase = phase0 + speed·n,
light_angle = 88 + n, levels as clamped ramps, pal_angle ≈ 0x944 + 0.5·n (or the exact music-row gating).

## 7. Shortcuts a high-resolution remake should evaluate exactly

Write everything in original-pixel units X ∈ [0,320), Y ∈ [0,200):
1. **Oscillators**: table sine with truncated 10-bit index → `amp·sin(2π·phase·2^cl/131072)/2^cl`.
2. **Patch**: 8x8-block bilinear interpolation of a 41x26 grid → evaluate per pixel
   `Q(P0,P1,P2;s) = P0 + (−3P0+4P1−P2)s + (2P0−4P1+2P2)s²`, rows first (`Rx_j = Q(P[j][0..2].x; s)`, s = 3X/1024),
   then `Xtex = Q(Rx_0,Rx_1,Rx_2; t)`, t = 5Y/1024 (same for Y). Texel coordinate = (Xtex/4, Ytex/4).
3. **Texture**: nearest lookup in a 256x256 byte texture built from a 64x64 4-bit image → sample filtered, or rebuild
   the 128x128 quadrant at higher resolution (upsample the nibble image, Gaussian σ ≈ 1.73 texels, mirror 4-way,
   shift −6 texels). Height = tex·20/32.
4. **Letters**: 1-bit 32-row font doubled vertically and cross-blurred 4 times (≈ Gaussian σ ≈ 1.41 screen px) → a
   smooth high-res glyph alpha (same font shape or a Helvetica-like vector font) blurred by σ ≈ 1.41 original px;
   height = max(background, alpha·255·level/32). The heights are 8-bit quantised in the original.
5. **Gradient**: byte central differences over ±1 original pixel, halved, 7-bit → use the continuous derivative in
   original units: gx = (h(X−1)−h(X+1))/2 ≈ −h'(X); the original never wraps (max |diff| 126), so no wrap emulation
   is needed. Index offset = gx (flat = 0; original adds 64 and the LM base absorbs it).
6. **Light map**: 512x256 bytes sampled at half resolution with floor(X/2) and no filtering → evaluate it analytically:
   with `u = X/2 + A − 80 + gx`, `v = Y/2 + E − 50 + gy` (light-map texels relative to the light centre),
   `index = min(255, radial(√(u²+v²)) + tex[(−(v+128))&255][(−(u+256))&255]/2)` using the §2c piecewise radial
   function in float (keep the core step at v = 192/193), and the texture term bilinearly filtered.
   A = 64·sin θ, E = 16·cos θ, θ = 2π·light_angle/1024 (the original floors both).
7. **Palette**: 256-entry 6-bit ramp → compute the colour from the index in float (§5e) and apply the fade
   multiplicatively.
8. The 1-pixel black border (rows 0/199, columns 0/319) is an artefact of the edge handling; drop it.

## 8. Not determined / caveats
- The starting light angle (88) is whatever the last 3D-scene computation left in [0x22469] (used there as a
  scratch vector component). It may differ on other machines. It only sets where the light starts (here left of
  centre, x ≈ 94 at the first frame).
- Light-map reads one row outside the 512x256 map (rows −1 / 256) are theoretically possible for the steepest letter
  edges at the top/bottom screen rows when E = ∓16. That memory is allocation padding, and I did not see it happen.
- The wave table above was taken from the reference run. It is deterministic as far as I can tell: every earlier
  random call happens in once-per-part set-ups. But I did not re-derive the random state from program start.
