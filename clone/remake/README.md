# clone meets clone by Acme & Fudge (Takeover '98) — high resolution remake

A C++/OpenGL re-implementation of *clone meets clone*, the 64k intro by Acme & Fudge (design Aap and Echo, effects
Echo, music Simon, graphics Aap; texture mapper and grid filler Craft, radial blur originally Dune) for MS-DOS. It
runs on Linux and Windows at any resolution in true colour, with the original's motion, timing and music, and with
high-resolution redraws of Aap's pictures (or the original pixels, `--original-art`).

**Status**: the framework, the music and the running order are in place; the parts are being ported (see
[`../re/PORT.md`](../re/PORT.md)). Parts that are not ported yet show a placeholder with their captions.

The remake reads everything from the original `CLONE.EXE` (63,994 bytes). It is not included: put it into
`clone/original/`.

| what | where in the exe | how it is used |
|------|------------------|----------------|
| the program image | a "VE" container behind PMODE/W and a small LE loader: LZ77 with canonical Huffman codes, a fixup list | unpacked at start-up by `src/unpack.cpp` (as the loader does it) and checked against the known release |
| the music | an MXM module in the image, completed by 20 samples the intro synthesises at start-up | built by `src/modsynth.cpp`, played by a port of its MXMPlay build (`src/mxmplay.cpp`) through a model of the GUS GF1 (`src/gf1.cpp`) |
| the running order | the sync table 0x420499 (positions → events) | the part events as music times (`src/timeline.cpp`) |
| the pictures | four captions, four glyphs, the title and the credits, 8-bit pixels with three grey palettes | the redraws in `art/`, or the original pixels (`src/pictures.cpp`) |
| the textures | generated by the intro from formulas | evaluated exactly at high resolution (`src/clone/textures.cpp`) |
| the rest | tables at image addresses (the tile colours, the random seed, the parts' parameters) | read by address where the parts need them |

All addresses are linear addresses of the program relocated for 0x400000; the notes in [`../re/`](../re/) explain
every one of them.

## Running

The program looks for `CLONE.EXE` next to itself, in its parent folders, and in an `original` folder in any of
those, so `clone/original/CLONE.EXE` is found from the build folder; or pass `--exe FILE`. The redraws are found
the same way in an `art` folder (`clone/remake/art`); or pass `--art DIR`.

```
clone-remake [--window] [--size 1280x960] [--start SECONDS] [--ss 2] [--loop] [--info] [--original-art]
```

Keys: `Esc` quit, `Space` pause, `←/→` seek ±5 s, `↓/↑` seek ±30 s, `F`/`F11` toggle fullscreen.
`--ss 2` renders at twice the resolution and downsamples. `--info` shows the time, music position, part and main's
time t70 in the title bar.

Offline: `--wav out.wav` writes the soundtrack; `--shots 10,62.5 --shotdir DIR --shotsize WxH` writes the frames at
those music times (seconds) to PNG (the folder is created); `--video out.mp4 --from T0 --to T1 [--fps 60]` renders
a range with sound through `ffmpeg`; `--bench T0,T1 --shotsize WxH` reports the GPU time per frame; `--cues` prints
the running order; `--picshots all --shotdir DIR` draws the pictures (or `mapA,mapB,mapC,table1,table2`, the
generated textures) to PNG.

## Building

Requirements: a C++20 compiler, CMake ≥ 3.20 and SDL3. If SDL3 is not installed, CMake downloads and builds it
(3.2.24); `-DCLONE_FETCH_DEPS=ON` always does that. No other libraries are used (`stb_image` and `stb_image_write`
are included in `third_party`).

```
cmake -S . -B build -G Ninja && cmake --build build
./build/clone-remake --window
```

Windows from Linux (MinGW): `mingw64-cmake -S . -B build-win -G Ninja && cmake --build build-win`.
`-DCLONE_PARTS="tube;zoom"` builds only those parts (development).

## Time

Music time t = xmpGetTimer / 1,193,182 s (0 = the first row sounds). The original integrates every animation by
dt = the change of its time t70 = timer / 17043 once per drawn frame; the remake evaluates the same state from t
(the part's clock starts where the capture's did, at the previous part's last frame) and steps what depends on the
frame rate at the capture's frame steps. Details in [`../re/PORT.md`](../re/PORT.md).

## Known differences

- Part changes and sync events happen at their music time; the original runs them at the first frame after it (up
  to one frame later, 1.4..38 ms in the reference capture).
- The intro ends at 216.910 s, after the frame that sees the last row (interrupt 11713 as in the capture; on a
  real machine it depends on the frame rate).
- Text redraws carry their grey as coverage of white: over the particles of part 1 the title has no dark rim
  (the original's anti-aliasing pixels are opaque).
