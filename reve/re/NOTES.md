# Reve (Pulse, 1995/96) — reverse-engineering notes

*Reve* ("REVE the return") by Pulse, 5th in the PC demo competition of The Party 5 (December 1995); this is the
"final version" of May 1996 (`REVE.EXE`, 999,999 bytes, sha256
`a2053c9c3112977d3593c9f0690d32f10a225471109750b4947af68b22507cd2`). MS-DOS, 32-bit protected mode under LCA's own
extender "FLAT OS V1.0", VGA mode 13h, music on a Gravis UltraSound (Sound Blaster and no-sound paths exist) by
"LCA's MOD-Player V3.03". Credits (NFO and the demo's own credits): code LCA and others of the French section, 3D and
graphics AJT, graphics Antony, music Shad.

## Files and tools

All tools run inside the toolbox (`toolbox run -c acme303 python3 ...`) from this folder. Generated files are made
from the original and stay out of Git (`unpacked/`, `snaps/`, `full.*`, `*.jpg`, `*.log`).

| file | what it does |
|---|---|
| `unpack.py ../original/REVE.EXE` | runs the real-mode loaders in unicorn up to the extender, unpacks the 36 files of the archive with a Python LZW checked against the extender's own decompressor; writes `unpacked/` |
| `rep.py` | capstone helper on `unpacked/reve_img.bin` (addresses as in the headless run): `func / dis / calls / xref / funcs / str / ints / ports` |
| `run_reve.py --out full` | runs the whole of `REVE.EXE` headless in unicorn, extender included (see "Running it headless") |
| `sheet.py full.frames out.jpg --every 2 --cols 6 --scale 0.5` | contact sheets of a capture (or `sheet.py full.frames out.jpg F1 F2 ...`) |
| `NOTES.md`, `PARTS.md`, `BRIEF.md`, `notes-*.md` | these notes, the timeline, the brief for the decompilers, one notes file per scope |

Generated by `unpack.py`: `unpacked/flatos.bin` (the extender as it is in memory when it starts, 0xc400 bytes from
linear 0x10000), `unpacked/reve_lfl.bin` (REVE.LFL unpacked), `unpacked/reve_img.bin` (its image relocated to
0x20427c), `unpacked/files/<path>` (the other 35 files), `unpacked/files.txt` (the archive with checksums and hashes).

**Addresses** in these notes are linear addresses of the running demo in the headless run, where the extender loads
the image at 0x20427c: address A is byte A - 0x20427c of `reve_img.bin` and byte A - 0x20427c + 0x1c of REVE.LFL.
The demo runs with flat selectors (base 0), so its pointers are these addresses. Buffers it allocates lie outside the
image (their addresses depend on the extender's allocator; the headless run's are given where useful). The
extender's own addresses are "kernel" offsets: its 32-bit segment has base 0x10c60 (segment 0x10c6), kernel offset
K = linear 0x10c60 + K = `flatos.bin` offset 0xc60 + K.

### The loaders (real mode)

The entry (image 0x0000) copies 7 words to 0000:0000 and jumps there; that code decrypts 0x27ae words from CS:0x40
to CS:0 (`w = ((w ^ 0x80ed) - 0x2d34)`) and returns to CS:0, where the next layer does the same with the next key,
64 layers in all, each 0x40 bytes shorter. The last layer leaves a packed loader whose unpacker (at 1CEC:0642 for load
segment 0x1000) writes LCA's FLAT OS to the load segment and jumps to its entry 1000:0000 with SS:SP 1C1D:0200.
`unpack.py` simply runs all of it (about 2.6 million instructions) and takes the memory when the extender makes its
first DOS call (int 21h AH=4Ah at 1000:0013); a C++ port does not need any of it.

### The archive and its LZW

Record (kernel lookup 0x9228): dword record size (header, name and data), dword unpacked size, dword checksum, byte
method (1), the name zero-terminated (`REVE.LFL`, `ZIC\PULSE.MOD`, `GFX\*.RAW|PAL`, `3D\*.WLD|ANI`), the compressed
data; the next record follows. The lookup compares names exactly (case sensitive, backslashes).

LZW (kernel 0x9284; bit reader 0x93c0, output 0x93f4, table 0x9414): codes read least significant bit first from a
dword at the current byte (`(dword >> bitpos) & mask`); start with 9 bits, mask 0x1ff, limit 0x200, next code 0x102.
Code 0x100 = end, 0x101 = reset (back to the start state; the next code is a first code). The first code after a
reset is output as a byte and becomes the previous code. Every later code c: if c >= next, the string is
string(previous) + first byte of string(previous); else string(c) (the table holds prefix code and last byte, 3 bytes
per entry); the string is output; entry next = (previous, first byte of the string), next += 1; previous = c; if
next reaches the limit and the width is below 13, width += 1 and limit doubles (no growth at 13 bits).
Checksum (0x93f4): `s = ror32(s + byte, 3)` over the output from 0; the record's checksum must match. All 36 records
unpack to their stated sizes and checksums, identically with `unpack.py`'s Python and the extender's own routine.

### REVE.LFL

Header (0x1c bytes): `"LCA's FLAT OS V1.0"`, 0xe1 0x1a, dword image size 0x6d9c0, dword entry offset 0. Then the
image, then `"LCAr"` and 2,937 dword image offsets of dwords to which the load address is added (kernel 0x1d30: the
extender loads the file with its own service 0209h, finds "LCAr", adds `0x10c60 + buffer + 0x1c` to each, and far-calls
the image's start with CS = selector 0x20 and DS = ES = FS = GS = SS = 0x28, both flat, AL = the memory mode).

## LCA's FLAT OS V1.0 (the extender)

"FLAT OS v1.0 (C) 1995-96 Cedric BERMOND (LCA/Pulse)". At start it checks the CPU (386+, `cpuid` when present), needs
XMS (HIMEM: int 2Fh 4300h/4310h; it allocates all free extended memory and locks it), then decides the memory mode
by whether the CPU is in V86 mode (`smsw`): in real mode it switches to protected mode by itself ("raw", mode 0); under
EMM386 it imports EMM's page tables ("EMM-Import", mode 2, via the EMMXXXX0 device and int 67h); with the command
line word `DPMI` it runs as a DPMI client (mode 1). It allocates all free conventional memory too. In raw mode it
reprograms the PICs (IRQ 0-7 to vectors 80h-87h, 8-15 to 88h-8Fh), builds its GDT at 0x1099c (selectors 0x08 / 0x10:
its own code and data, base 0x10c60; 0x18: base 0x10000; 0x20 / 0x28: flat code and data, base 0) and an IDT of 256
interrupt gates at kernel 0x1e88, and serves:

- **int 0FFh**, the extender's API, AH = group, AL = function (dispatcher kernel 0x95c0, groups 0x8640 / 0x874c /
  0x8974 / 0x9438 / 0x74b0): 01xxh memory (0101h allocate EBX bytes → EBX, 0102h free), 02xxh files (0200h open,
  0201h close, 0206h size, 0207h read, 0209h load a file of the archive by name ESI → EDI, size ECX; 020Dh set the
  archive name), 03xxh (0305h keyboard state pointer → EBX), 04xxh text output and errors, 00xxh IRQ handlers (0003h
  set, 0004h get, 0005h / 0007h DMA buffers);
- **int 0FEh**: call a real-mode interrupt (AL) with a register block;
- hardware IRQs: its stub reads the PIC's in-service register (OCW3 0Bh) and calls the handler registered for that
  IRQ with service 0003h.

The headless run needs none of this to be understood: it runs the extender.

## The demo's program flow

Entry 0x20427c (AL = memory mode → [0x205cd3]): 0x204296 parses the command line (`NOSOUND`, `MIX:nn`, `MONO`,
`8BIT`) and starts the sound system: 0x25f698 detects the card (GUS by the `ULTRASND` variable, else Sound Blaster
probes at 0x210..0x280; [0x260406] = 0x20 for a GUS, 1..4 for SB types, 0 for none), 0x2175bc fills a table at
0x219ec8 (byte n repeated 2n+1 times: integer square roots), service 0305h → [0x205e7c] (keyboard state),
allocates 0x51100 bytes: [0x205e80], [0x205e84], [0x205e88], [0x205e8c], [0x21b140] five 64 KB buffers, [0x205e90]
256 bytes, [0x205e94] the rest; sets mode 13h (int 0FEh AL=10h AX=13h), clears the screen, 0x25a1bc patches the
addresses of [0x205e90] / [0x205e94] into the code between 0x25a7dd and 0x25eae9 (placeholders 0x12345678 /
0x87654321), and loads and converts the module 0x2601dc (`ZIC\PULSE.MOD`; for a GUS it uploads the samples by DMA).

main 0x204770: 0x204458 installs the timer (below), 0x2602a1 starts the music, then runs the script table.

### The script table 0x205ed0

30 entries of 0x14 bytes, ended by a zero dword: `{init, done, retrace routine, frame routine, end position}`. For
each entry main calls init (with the retrace routine set to the empty 0x20483f meanwhile), sets the retrace routine
[0x205e9c], clears the flag [0x205e9a] and sets the end position [0x205ea0]; then loops: 0x2045d0 (wait for a
retrace, below), the frame routine; until the timer interrupt has set the flag (music position >= end position, as
the word order << 8 | row); then calls done and goes to the next entry. ESC (the keyboard state at [0x205e7c] + 1)
ends the loop. After the last entry: 0x20538d, 210 more retraces, 0x2602c6 stops the music, 0x2044a4 restores the
timer. PARTS.md lists the entries.

### The clock: a retrace-locked timer

0x204458 installs the IRQ 0 handler 0x2044cc (service 0003h) and programs the PIT (channel 0, mode 3) with 0x40d8.
The handler: if the vertical retrace has already started (0x3da bit 3), the count was too long: the immediate at
0x20453d (the count) is decremented; else it is incremented and the handler waits for the retrace; then it reloads the
PIT with that count (0x204538), so the interrupt settles to fire just before each retrace (counts 0x427f / 0x4280 in
the capture: 70.09 Hz) and the handler returns right at the retrace. (A second variant with the count at 0x204516,
0x4c2c, is used when [0x205e99] = 1; the demo clears it.) Then, every refresh: EOI, `sti`, [0x205e98] += 1 (retraces
since the last frame), without sound card 0x271ad3 advances the music position, 0x2602eb reads the music position
(order in AH, row in AL), swapped to order << 8 | row and compared with [0x205ea0] (≥: [0x205e9a] = 1), and the
retrace routine [0x205e9c] is called unless it is still running from the last interrupt ([0x205cd2]).

The frame wait 0x2045d0: in raw mode, waits until [0x205e98] >= 1, then sets it to 0. So the main loop draws at most
one frame per refresh: a frame that takes less than a refresh waits for the next retrace; a longer one starts the
next at once. (With AL = 1 at start, the DPMI mode, it polls the retrace itself.)

So there are two clocks besides the music: **the refresh** (70.086 Hz: the retrace routines run once per refresh) and
**the drawn frame** (the frame routines, at most one per refresh). What a frame routine advances per call is frame-rate
dependent; the part notes say which.

### Music

LCA's MOD-Player V3.03 ("LCA's Player, (C) Cedric BERMOND (LCA) 1993-95 Version 3.03"), a later version of the player
in STARS (stars/re/NOTES.md "Music", stars/remake/src/lcaplay.cpp: V3.02); notes-music.md has it all, with the
differences from V3.02. Card in [0x260406]; position: order [0x26042d], row [0x26042c] (0x2602eb returns them in
AL / AH; the timer interrupt swaps them into order << 8 | row). The module plays on the GUS's own timers (80 BPM on
timer 2, 31.04 ms per tick, and 150 BPM on timer 1, 16.64 ms), started at refresh 29.0000 of the capture; main stops
the music 210 refreshes after the last entry's end position 64:63, at refresh 17,728.

## Running it headless (run_reve.py)

Unlike the other remakes' runners, `run_reve.py` starts at the MZ entry and runs everything: the loaders, the extender
(which switches to protected mode by itself because the emulated CPU is in real mode) and the demo. It answers only
what DOS, the BIOS and HIMEM would: int 21h (memory, files: REVE.EXE from ../original, the PSP, the DTA), int 10h,
int 15h, int 16h, int 1Ah, int 2Fh 43xxh and the XMS entry point (15 MB at 0x110000). Interrupts are delivered as the
CPU would, through the IVT in real mode and through the extender's IDT in protected mode; the extender reflects its
DOS calls to real mode and they reach the runner there.

- Unicorn runs in its 32-bit mode started in real mode (CR0 = 0x10): in its 16-bit mode `emu_start` sets
  EIP = (start - CS * 16) & 0xffff, which breaks as soon as the extender runs 32-bit code above 64 KB.
- Faked hardware: both PICs (initialisation words, masks, IRR/ISR reads through OCW3, EOI), the PIT channel 0, the VGA
  (mode 13h at 0xa0000, the DAC, 0x3da with 449 lines per refresh, 70.086 Hz; sequencer / CRTC / GC writes are logged:
  the demo makes none in mode 13h), the 8237s, and a GUS at 0x240 (`ULTRASND=240,3,3,7,7`) with its timers and DMA
  uploads (the Gus class of stars/re/run_stars.py).
- Time: the PIT clock. Code runs at `--ips` instructions per second (default 100 million, a Pentium as the NFO
  recommends) including interrupt handlers; a loop that reads 0x3da at the same place and gets the same value jumps
  to the next change.
- Records: one per refresh at the start of the vertical retrace (line 412): `.frames` (b'REVEFRM1', <IIII 320, 200,
  64768, 24; then 64,000 bytes of VGA memory and the 768-byte DAC), `.ticks` (frame, time, PIT interrupts, GUS timer
  interrupts, order, row, the main-line PC when no IRQ was in service), `.gus` (GUS writes stamped with the GUS timer
  interrupt count), `.dram`, and the log (services, files, mode switches).
- `--snap-at F1,F2 --snapdir DIR` saves snapshots (pickle: 'mem' 16 MB, 'ctx', 'st', 'gus', 'dma', 'pic1', 'pic2',
  'pc'); `--load --snap FILE` resumes; `--history N` prints the last N jumps on an emulation error; `--trace A,B`
  prints when an address first runs.
